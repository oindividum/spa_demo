## 1. Задача: Пропорциональное распределение средств (PreciseDistributor)

### Описание логики

**Дано:**
- `amounts` (список балансов)
- `withdrawalAmount` (общая сумма к снятию)
- `scale` (точность)
- `allowOverdraft` (можно ли уходить в минус)

**Требуется:**
Распределить сумму к снятию поровну (пропорционально балансам) и вернуть `List<BigDecimal> withdrawalAmounts`.

**Ограничения:**
1. `SUM(withdrawalAmounts) == withdrawalAmount`
2. `withdrawalAmounts(i) <= amounts(i)`
3. Максимальное сохранение пропорций с учетом `scale`

### Мое решение - Метод наибольшего остатка

Основная проблема задачи — бесконечные дроби. Если использовать обычное округление, типа `HALF_UP`, то после сложения всех долей почти всегда мы либо теряем копейки, либо списываем лишнее, что может увести счет в минус / овердрафт.

Разбила алгоритм на два шага:

**Шаг 1. Безопасное усечение (down)**

Сначала считаем математическую долю:
`amount * distributeAmount / totalAmount`

Но не округляю её по правилам математики. Используем `RoundingMode.DOWN` (жесткое усечение вниз до нужного `scale`). Разницу между идеальной долей и усеченной (отрезанный хвост) сохраняю в отдельный класс `Remainder`.

Плюс этого подхода:
сумма всех усеченных списаний гарантированно `<= distributeAmount`. Уйти в минус на этом этапе невозможно.

**Шаг 2. Распределение копеек (Shortfall)**

Так как были усечены хвосты, у нас остается недосписанный остаток (парочка копеек), который нужно раздать. Возникает вопрос: куда их??

Сортируем счета по убыванию отброшенного остатка (кто потерял при усечении больше всех). И раздаем недостающие копейки, например, если `0.01` при `scale = 2`, им по очереди, пока общая сумма не сойдется.

Перед каждым `+unit` будет делаться проверка на `allowOverdraft`.

Спасибо нейронке, которая по выше написанному создала блок кода:

```java
for (int i = 0; i < amounts.size(); i++) {
    BigDecimal exactShare = amounts.get(i).multiply(distributeAmount)
            .divide(totalAmount, scale + 4, RoundingMode.DOWN);
            
    // Усекаем до нужного scale
    BigDecimal truncatedShare = exactShare.setScale(scale, RoundingMode.DOWN);
    distributed.add(truncatedShare);
    distributedSum = distributedSum.add(truncatedShare);
    
    // Запоминаем отрезанный хвост
    remainders.add(new Remainder(i, exactShare.subtract(truncatedShare)));
}

// Шаг 2. Распределение оставшихся копеек
BigDecimal shortfall = distributeAmount.subtract(distributedSum);
BigDecimal unit = BigDecimal.ONE.movePointLeft(scale); // единица нужного scale (напр., 0.01)

// Сортируем счета по размеру потерянного хвоста (по убыванию)
remainders.sort((a, b) -> b.remainder.compareTo(a.remainder));

int i = 0;
while (shortfall.compareTo(BigDecimal.ZERO) > 0) {
    int idx = remainders.get(i).index;
    
    // Проверка лимитов (allowOverdraft) происходит здесь...
    
    // Добавляем 1 копейку
    distributed.set(idx, distributed.get(idx).add(unit));
    shortfall = shortfall.subtract(unit);
    
    // Берем следующий счет (или идем по кругу)
    i = (i + 1) % remainders.size();
}
```

## 2. Задача: Интеграция M3U Медиаплеера (PlaylistPlayer.tsx)

### Условия задачи
- **Требуется:** Написать компонент плеера для воспроизведения `.m3u` плейлистов в SPA.
- **Ограничения:** Уметь корректно парсить файлы, строить пути для аудио/видео из относительных ссылок и автоматически переключать треки.

### Как я это решила

**Парсер без NPM-библиотек**
Изначально была проблема: треки не грузились (ошибка `Unexpected token`). Я переписала парсер файла: скачиваю `.m3u` через `fetch` и делю его строго по переносу строки `/\r?\n/`, а не просто по запятым. Затем фильтрую мусор и метаданные (`#EXTINF` и т.д.), выцепляя чистые названия треков.

**Резолв путей**
Так как в `.m3u` обычно лежат не абсолютные URL, а просто имена (типа `track1.mp3`), я написала логику, которая склеивает переданный в пропсы `basePath` с именем файла, чтобы плеер знал, откуда тянуть медиа (`/fidds/v1/...`).

**Управление плеером (Audio/Video)**
Сам движок — это просто нативные теги `<audio>` и `<video>`. 
Для управления стейтом:
- Храню `currentIndex` в `useState`.
- Использую `useRef`, чтобы напрямую дергать `mediaRef.current.play()`, когда юзер кликает по списку треков.
- Для бесшовного включения следующей песни добавила слушатель на `onEnded`, который просто делает `setCurrentIndex(prev => prev + 1)`.

Компонент аккуратно рендерится внутри постов при наличии `.m3u` в списке `files`.
